# Проверки Sana

Дата: 23 ноября 2026 года. Среда: Windows, Node.js 24.13.0, Expo SDK 58, React Native 0.88.1.

## Пройдено

- TypeScript: `npm run typecheck`, без ошибок.
- `npm test`: 7 тестов успешно. Проверяются полнота RU/KK материалов и 69 уникальных ID, корректность заданий, решаемость лабиринта, объединение прогресса, наличие озвучки, регистрация и вход, изоляция аккаунтов, две сессии одного ученика, отказ в доступе без токена, удаление аккаунта, проверка входных данных, ограничение запросов и частичная загрузка аудио.
- `npm run test:e2e`: 4 браузерных сценария успешно. Полностью пройдены все 69 уроков; проверены пять видов упражнений, перезагрузка и сохранение, переход на казахский, компоновка 390×844 и 1280×900, объединение прогресса двух устройств после офлайн-прохождения, повторный запуск без сети, реальное продвижение воспроизведения RU/KK аудио без сети.
- `py scripts/validate_audio.py`: 138 MP3 декодируются без ошибок, длительность около 51.9 минуты, объём около 18.7 МБ. Пофайловый отчёт: `generated/audio-validation.json`.
- `npm run build:web`: production-веб-сборка, manifest и service worker; 145 ресурсов включены в офлайн-кеш.
- `npm run build:native`: экспорт Hermes-пакетов Android и iOS вместе с 138 MP3.
- Android: `assembleRelease` успешно, ARM64 APK для Android 7.0+; подпись v2 проверена через `apksigner`. Внутри подтверждены 138 MP3 и встроенный Hermes bundle (1 533 980 байт). Файл `deliverables/Sana-Android-arm64.apk` подписан демонстрационным debug-ключом, не предназначен для публикации в Google Play.
- `npx expo-doctor`: 20 из 20 проверок.
- `npm audit`: обнаруженных уязвимостей 0 на момент проверки. Для транзитивного minimatch закреплена исправленная ветка 11. Это не гарантия отсутствия всех уязвимостей.
- Визуально просмотрены снимки главного экрана и казахского урока на мобильной ширине.

## Границы проверки

Автоматизированные браузерные проверки не заменяют запуск на физических Android/iPhone/iPad. Android APK собран, но на устройстве не запускался. iOS IPA не собран: нет авторизованного Expo/Apple Developer аккаунта для подписи. Сервер проверен локально, публичное размещение не выполнено. Педагогическая эффективность и редактура носителем казахского языка не проверялись.

## Windows и пути

Expo prebuild в исходной папке с кириллицей ошибочно не находил MainApplication. Через ASCII junction prebuild прошёл, но Gradle разрешал реальный путь с кириллицей. Поэтому APK собран из отдельной копии проекта `C:\Users\ilaxg\.codex\sana-native-work`. Для повторной нативной сборки нужен короткий физический путь без кириллицы. Плагин `plugins/with-short-cmake.cjs` задаёт `CMAKE_OBJECT_PATH_MAX=240`, устраняя превышение длины путей Ninja. Использованы JDK 17, Android SDK 37.0, Gradle 9.4.1 и команда `gradlew.bat assembleRelease --no-daemon --max-workers=2 -PreactNativeArchitectures=arm64-v8a -Pandroid.enableMinifyInReleaseBuilds=false`. Генерируемые нативные каталоги не являются источником истины: конфигурация хранится в `app.json` и плагине.
