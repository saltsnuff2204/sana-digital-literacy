# Развёртывание сервера

Сначала `npm run build:web`, затем из корня проекта `docker build -f server/Dockerfile -t sana .`. Запуск: `docker run -p 8787:8787 -v sana-data:/app/server/data -e ALLOWED_ORIGINS=https://your-domain.example sana`.

Поставьте HTTPS reverse proxy перед портом 8787. `ALLOWED_ORIGINS` — список разрешённых web origins через запятую; нативные клиенты не используют CORS. Не добавляйте секретов в переменные `EXPO_PUBLIC_*`. Сервер доверяет адресу TCP-клиента для ограничения попыток, а не произвольному `X-Forwarded-For`; при reverse proxy настройте дополнительное ограничение запросов на самом proxy.

Сохраняйте резервную копию SQLite согласованным способом (SQLite backup API либо при остановленном сервере). Не копируйте только основной `.db` в момент записи без WAL. Том Docker обязателен для сохранения аккаунтов после пересоздания контейнера.

Вход ограничен 30 запросами за 15 минут на IP. Сессии живут 30 дней. Удаление аккаунта удаляет связанные серверные сессии и прогресс каскадно. Данные на другом офлайн-устройстве не могут быть удалены удалённо до подключения; очистите данные приложения на таком устройстве отдельно.

Перед публичным использованием нужны эксплуатационный мониторинг, процедура восстановления аккаунта, политика хранения детских данных и согласованные школьные правила. Текущий сервер достаточен для локальной демонстрации, но не объявлен проверенным production-сервисом.
